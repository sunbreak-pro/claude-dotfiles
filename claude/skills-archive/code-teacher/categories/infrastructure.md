# インフラ・運用

## カテゴリ概要

ソフトウェアが実際に動く環境と、それを維持する技術に関する知識。
「なぜ Docker を使うのか」「ログはどう見ればいいか」を理解する力を育てる。

## 関連カテゴリ

- **コンパイル・ビルド**: CI/CD はビルドとデプロイの自動化
- **ネットワーク**: インフラ設計はネットワーク知識が前提
- **設計・アーキテクチャ**: アーキテクチャの選択がインフラ構成を決める

## 難易度定義

### Lv.1 ★☆☆☆☆ — 環境を「知る」

**到達目標**: 開発環境・ステージング・本番環境の違いを理解し、基本的なデプロイの概念がわかる

**理解すべきこと:**
- 開発環境、ステージング、本番環境の違いと役割
- 「デプロイ」とは何か（コードを動く場所に置く）
- 環境変数とは何か、なぜ必要か
- ローカル開発サーバーの仕組み（`npm run dev` で何が起きるか）
- クラウドとオンプレミスの基本的な違い

**クイズ例:**
- 「なぜ本番環境と開発環境で違う設定を使うのか？」
- 「`NODE_ENV=production` を設定すると何が変わるか？」

---

### Lv.2 ★★☆☆☆ — コンテナを「使う」

**到達目標**: Docker の基本コマンドを理解し、Dockerfile を読めるようになる

**理解すべきこと:**
- コンテナ化とは何か（仮想マシンとの違い）
- Docker の基本: イメージ、コンテナ、ボリューム
- Dockerfile の基本命令（FROM, COPY, RUN, CMD, EXPOSE）
- docker-compose の役割（複数コンテナの管理）
- 「ポートマッピング」の仕組み（-p 3000:8080 の意味）
- ログの見方（`docker logs`）

**クイズ例:**
- 「この Dockerfile の各行が何をしているか説明せよ」
- 「docker-compose.yml のサービス間はどうやって通信しているか？」
- 「コンテナを再起動するとデータが消えるのはなぜか？永続化するにはどうするか？」

---

### Lv.3 ★★★☆☆ — CI/CD を「構築する」

**到達目標**: CI/CD パイプラインの構成を理解し、基本的なデプロイ自動化を設計できる

**理解すべきこと:**
- CI（継続的インテグレーション）: テスト自動実行、ビルド検証
- CD（継続的デリバリー/デプロイ）: 自動デプロイの仕組み
- GitHub Actions / GitLab CI の設定ファイルの読み方
- 基本的な監視: ヘルスチェック、アップタイム監視
- ログ管理の基礎（構造化ログ、ログレベル）
- シークレット管理（GitHub Secrets, AWS Secrets Manager）

**クイズ例:**
- 「この GitHub Actions ワークフローの各ステップの目的を説明せよ」
- 「テストが通ったら自動デプロイする CI/CD パイプラインを設計せよ」
- 「このログ出力を構造化ログに書き換えよ」

---

### Lv.4 ★★★★☆ — 可観測性を「設計する」

**到達目標**: オブザーバビリティの3本柱（ログ・メトリクス・トレース）を理解し、運用設計ができる

**理解すべきこと:**
- オブザーバビリティの3本柱: ログ、メトリクス、分散トレース
- メトリクス設計（RED: Rate, Error, Duration / USE: Utilization, Saturation, Errors）
- アラート設計（ノイズ低減、エスカレーション、On-Call ローテーション）
- Kubernetes の基本概念（Pod, Service, Deployment, Ingress）
- IaC（Infrastructure as Code）: Terraform / CloudFormation の考え方
- 障害対応の基礎（インシデント管理、ポストモーテム）

**クイズ例:**
- 「このサービスに必要なメトリクスを RED メソッドで設計せよ」
- 「アラートのノイズを減らすための戦略を3つ提案せよ」
- 「この Kubernetes マニフェストの問題点を特定せよ」

---

### Lv.5 ★★★★★ — インフラを「戦略的に設計する」

**到達目標**: 大規模システムのインフラアーキテクチャ、災害復旧計画、コスト最適化を設計できる

**理解すべきこと:**
- マルチリージョン/マルチクラウド戦略
- 災害復旧（DR）設計（RPO/RTO の定義、フェイルオーバー戦略）
- コスト最適化（リザーブド vs スポット、オートスケーリング戦略）
- GitOps の設計思想
- プラットフォームエンジニアリング（IDP: Internal Developer Platform）
- カオスエンジニアリング（意図的な障害注入によるレジリエンス検証）

**クイズ例:**
- 「このサービスの DR 計画を設計せよ（RPO: 1分, RTO: 5分）」
- 「月間インフラコストを30%削減する計画を提案せよ」
- 「カオスエンジニアリングの導入計画を立案せよ」
