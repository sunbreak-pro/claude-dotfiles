# メタハーネス構想 — ハーネスの中で自由に考えるための設計原則

> 恒久文書（docs/ 直下 = 非常駐・呼ばれたときだけロード）。実施手順は `docs/plans/2026-08-13-agent-portfolio-and-meta-harness.md`、コスト面の土台は `docs/plans/2026-08-13-context-efficiency-rollout.md` を参照。

## 一言でいうと

ハーネス（rules / hooks / skills / agents / permissions）は職場のルールブックである。いまのルールブックは「手順書が細かい職場」に近く、動きは正確になる代わりに考える余白が減る。メタハーネスとは、これを **「手順を指定する」から「目的と境界だけ指定して、やり方は任せる」へ引き上げ、さらに働く本人（Claude）がルールブックの改善を提案できる目安箱を備えた状態** を指す。

## 設計原則

### 1. 境界は太く、手順は書かない（goal-shaped rules）

- rule には「何を守るか」（目的・境界・完了条件）だけを書く。「どうやるか」の手順を書きたくなったら、それは常駐 rule ではなくオンデマンドの skill に置く。
- 役割分担: **rules = 判断基準（常駐・短い） / skills = 手順書（呼ばれたときだけ） / docs = 背景知識（参照されたときだけ）**。
- 手順を細かく書くほど、想定外の状況でルールの字面と目的が食い違い、思考が字面に縛られる。境界だけ引いておけば、境界内の判断は状況に合わせられる。

### 2. 自由の原資はコンテキストの余白

- 机が書類で埋まっていると、自由に考える場所がない。常駐ロード（CLAUDE.md・paths 無し rules・skill/agent の description）の最小化は、メタハーネスの前提条件である。
- 具体策は context-efficiency 計画（P1〜P3）に委ねる。本書は「痩身は倹約のためでなく思考の余白のためでもある」という位置づけだけを与える。

### 3. 自己観測 → 提案 → 人間ゲート → 反映のループ

- Claude が自分の稼働実績を観測できるようにする。観測対象（摩擦シグナル）:
  - エージェント / スキルの起動実績（`~/.claude/projects/*/*.jsonl` の集計）
  - permission 拒否・hook 失敗・SSE ハング等の障害痕跡
  - 「rule に書いてあるのに毎回無視される / 毎回同じ確認が挟まる」型の運用のきしみ
- 観測結果から dotfiles への変更（rule の痩身・agent の廃止・skill の新設）を **diff の形で提案** する。
- 反映は必ず人間ゲートを通す: git ブランチ + ユーザー承認。**hook による自動書換はしない**（暴走と回帰の温床。目安箱であって自動改訂ではない）。

### 4. 規範は宣言、強制は決定論

- 本当に守らせたいことは hook（決定論・fail-open）で担保し、rule の文面は最小限に保つ。
- 逆に、hook で守れていることを rule に長文で重ねて書かない（文面が増えるほど常駐が太り、原則 2 に反する）。
- 例: skill 起動通知は `skill-launch.md`（宣言）+ `skill-launch-notice.mjs`(強制) の 2 点セットで、各 SKILL.md への転記を廃止済み。この型を標準とする。

### 5. エスカレーションは処方箋より梯子

- 「必ずこの順で全工程を踏む」型の処方箋ではなく、「軽く始めて、失敗の証拠が出たら一段上げる」型の梯子にする。
- 例: メイン直接 → 軽量サブエージェント → メイン引き取り（= 最上位モデル）。工程の追加は「失敗の実測」をトリガーにする。
- エージェント・工程の新設も同じ物差しで判断する: **実測の痛みが先、インフラが後**（7/19 コスト最適化計画の Phase 2 判定と同じ思想）。

## 先行事例（2026-08-13 調査、詳細は同日の plan 参照）

- Anthropic Managed Agents の "dreaming"（セッションとメモリを定期レビューし整理。人間レビュー付き更新を選択可）と Outcomes（別コンテキストの grader が評価 = 自己評価の甘さを分離）。本書の原則 3 と同型だが、**Managed Agents 製品の機能であり Claude Code CLI には無い**。CLI 側でやるなら自前実装になる。
- コミュニティの self-improving-skills 系: stop hook + `/reflect` でセッションを分析し SKILL.md へ反映。安全策はスナップショット + ロールバック + 予算上限。
- Anthropic は自律サブエージェント生成に濃度・深度・総数の制限を 2026-07〜08 に段階導入した。**自由度を上げるときは暴走対策を同時に入れる**のが公式の実例であり、本書が人間ゲートを外さない理由でもある。

## この構想が「しないこと」

- rule / skill の全面リライト運動はしない。改訂は摩擦シグナルが指した箇所だけ、diff 単位で行う。
- Claude による settings.json / hooks の自動変更はしない（提案まで）。
- 記憶系の新設はしない（task-tracker / auto memory / sui-memory の境界は `rules/memory-boundary.md` が正本）。

## 語彙

| 語           | 意味                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| ハーネス     | Claude の実行環境を形づくる rules / hooks / skills / agents / permissions の総体 |
| メタハーネス | ハーネス自体を観測・改善の対象にする一段上の設計層                               |
| 常駐層       | 毎セッション自動ロードされるもの（CLAUDE.md・paths 無し rules・description 行）  |
| 摩擦シグナル | 使用実績・拒否・失敗・きしみなど、ハーネス改善の根拠になる観測データ             |
| 観測ループ   | 摩擦シグナル収集 → 変更提案 → 人間ゲート → 反映、の一巡                          |
