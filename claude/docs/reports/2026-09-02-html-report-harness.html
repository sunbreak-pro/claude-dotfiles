CLI から HTML を書いて、すぐ見て、残すための最小構成

追加インストールなしで今日から回せる案を先に置き、増やすもの・入れないものを分けました。このページ自体がその案の第 1 号です。

  • 今日から

    Artifact ツール + リポジトリ内 docs/reports/

    Claude Code に載っている Artifact 発行機能で claude.ai に非公開 URL を作り、同じ HTML をプロジェクトの docs/reports/ に git 管理で残す。ローカルで見るときは Start-Process で既定ブラウザを開く。

  • 必要になったら

    VS Code Live Preview / watchexec

    同じ HTML を何度も直して眺める作業が出たときだけ。VS Code は導入済みなので拡張 1 つで済む。watchexec は winget で入る。

  • 入れない

    新しいノートアプリ（Trilium / Obsidian / Logseq）

    保管庫としては優秀でも、アプリが 1 つ増えると判断の置き場が分散する。こうだいさんの場合は life-editor の Note が既に「自分のノートアプリ」なので、そこに MCP で要約を流す。

流れは 3 段だけ

01 WRITE

Claude が HTML を書く

判断材料が 3 つ以上並ぶとき、比較表・スクショ・進捗のときだけ HTML にする。1 問 1 答はターミナルの文章のまま。

置き場: docs/reports/YYYY-MM-DD-slug.html

02 VIEW

すぐ開く

Artifact 発行なら URL が返り、ターミナルでは Ctrl+] で直近のページを再表示できる。ローカルは PowerShell で 1 行。

Start-Process .\docs\reports\x.html

03 KEEP

残して探せる

claude.ai/code/artifacts の一覧と、git の docs/reports/ の 2 か所。結論だけを life-editor の Note に MCP で流せば、スマホからも読める。

確認済みの事実: 調査エージェントは「Artifacts は Team / Enterprise 限定」と報告しましたが、このセッションには Artifact ツールが載っています。本ページの発行がその実証で、URL が出ていれば無料枠で使えています。

この PC にあるもの・ないもの

2026-09-02 に where.exe と winget list で実測。

道具導入役割入れ方向き
Artifact ツール（Claude Code）ありHTML を claude.ai に発行・一覧・再表示不要判断材料の共有と保管。16MB 上限、外部スクリプトは cdnjs 等のみ
PowerShell Start-Processあり既定ブラウザでファイルを開く不要単発表示。ライブリロード無し
VS CodeありLive Preview 拡張で保存時に自動更新拡張 1 つ同じページを何度も直すとき
Node / Pythonありpython -m http.server で file:// 制約を回避不要fetch や ES module を使う HTML だけ必要
watchexecなし保存を監視して任意コマンド実行winget install watchexec.watchexec自動で開き直したいとき
browser-sync / live-serverなしライブリロード付きローカルサーバーnpm i -g browser-synclive-server 本家は 2026-06 にアーカイブ。使うなら browser-sync
quarto / marp / typst / pandocなしMarkdown から HTML / スライド / PDFwinget / npmClaude が直接 HTML を書くなら不要
Trilium / Obsidian / Logseq / SiYuanなしHTML やノートの保管庫各公式life-editor Note があるので見送り
life-editor MCP（Note 作成）stdio 直叩きで可結論を Note に流すこのセッションは未登録。/mcp 登録は life-editor 側の設定要約向き。生 HTML は貼れない（ブロック構造）

ハーネスとして固定するもの

枠組みは「いつ HTML にするか」「どこに置くか」「どう開くか」の 3 つの約束だけです。台所の定位置決めと同じで、置き場が決まっていれば探す時間が消えます。

いつ
選択肢が 3 つ以上ある判断、比較表、スクリーンショット付きの確認、進捗の俯瞰。1 つの答えを返すだけならターミナルの文章
どこ
プロジェクトなら docs/reports/YYYY-MM-DD-slug.html（life-editor には 2026-06-19 の HTML レポートが既にあり、前例に沿う）。プロジェクト外なら dotfiles の claude/docs/reports/
どう開く
Artifact 発行を第一候補、失敗したら Start-Process。両方の結果（URL とパス）を報告の末尾に必ず書く
見た目
1 ファイル完結・ライト / ダーク両対応・結論カードを最上段に。フォントは判読性重視の UD 系（本ページは BIZ UDPGothic）
残し方
git に commit。判断が要るものは結論だけ life-editor Note に流し、本文は URL で参照

この約束はグローバル skill html-report として dotfiles に置くのが収まりがよいです（description は起動条件だけ、テンプレートは本文に）。今回は設計までで、skill ファイルは作っていません。

PowerShell からの最短手順

# 1. Claude Code に「HTML で」と頼む → docs/reports/ に書かれ、Artifact の URL が返る
# 2. ローカルで開く（既定ブラウザ）
Start-Process .\docs\reports\2026-09-02-html-report-harness.html

# 3. 直しながら眺めるときだけ（VS Code Live Preview を入れていれば）
code --goto .\docs\reports\2026-09-02-html-report-harness.html

# 4. 直近の Artifact をターミナルから再表示
#    Ctrl+]   または   /artifacts
