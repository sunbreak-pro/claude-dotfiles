# Bash / Tool Execution Stability

Bash 等のツール実行直後に Claude の出力が止まる／固まるハングへの対処方針。

## 結論（原因は本体側・ローカルはシロ）

このハングの原因は **Claude Code 本体の SSE ストリーミング処理のバグ**。ローカル環境・hook・MCP 設定は無関係（実測で検証済み）。**「hook を無効化して直す」は無意味**なので、まずローカル要因を疑って調査時間を溶かさない。

2系統ある（`~/.claude/projects/<slug>/*.jsonl` を grep して分離可能）:

- **混雑系**: `529` / `Overloaded` / `rateLimit` — 夕方17時・夜22時に偏る（サーバー過負荷・時間帯依存）
- **接続切断系**: `ECONNRESET` / `terminated` / `socket hang up` / `ETIMEDOUT` — 深夜含め全時間帯にバラつく（時間帯非依存。「空いてる深夜でも止まる」の正体）

関連 Issue（修正は Anthropic 待ち）: **#25979**（SSE に read timeout が無い・open）/ **#53328**（tool_use 後の `message_stop` ドロップ）

## 再発時の対処フロー（これが主軸）

1. **ESC で復帰**（kill 不要なことが多い）
2. 系統判定: `grep -hE 'ECONNRESET|terminated|"status":529|Overloaded' ~/.claude/projects/<slug>/*.jsonl`
3. 混雑系なら **混雑帯（夕方17時・夜22時）を避ける**
4. 現行犯確保: 次回は **`claude --debug`** で起動 → ハング直前の最終ログが残る
5. hook / MCP / 環境いじりは無駄と即断（本体側の問題のため）

## 補助策: サブエージェント / バックグラウンド経由（効くかもしれない・根本解決ではない）

サブエージェント（Agent ツール）も同じ本体・同じ SSE を使うため、ハングの**根本は解決しない**（子側で同じバグを踏む。親＋子で SSE のやり取りが増える分、むしろ踏む機会が増える場合もある）。ただし副次効果として **メイン会話側がツール実行直後の区間に入る頻度を下げられる**ため、限定的に有効:

- **長時間 / ブロックする Bash**（ビルド・テスト・ログ追従・パッケージインストール等）は `run_in_background: true` か Agent ツール経由に逃がし、メインの SSE ストリームを長時間開きっぱなしにしない
- **軽いコマンド**（ls / git status / 単発 grep 等）は直接実行のまま。全ツールをサブエージェント経由にするのは **コスト（トークン・レイテンシ）だけ確実に増えて効果は不確実** なので避ける
- サブエージェント経由は生出力が要約されて見えにくくなる。**デバッグ中は直接実行のほうが速い**

## 適用の優先順位

1. 起きたら ESC →（必要なら）系統判定 → 混雑帯回避（これで大半は回る）
2. 重い／長時間のツールは最初からバックグラウンド or サブエージェントに逃がす（予防的）
3. それでも頻発するなら `claude --debug` で証拠を取り、本体 Issue の進捗を待つ
