# コンパイル・ビルド

## カテゴリ概要

ソースコードが実行可能な形になるまでの過程に関する知識。
「なぜビルドが必要か」「この設定は何のためか」を理解する力を育てる。

## 関連カテゴリ

- **インフラ・運用**: CI/CD パイプラインはビルドプロセスの自動化
- **デザインパターン**: 一部のパターンは言語・ランタイムの特性に依存
- **ネットワーク**: バンドルサイズは配信パフォーマンスに影響

## 難易度定義

### Lv.1 ★☆☆☆☆ — ビルドを「実行する」

**到達目標**: `npm run build` や `go build` が何をしているか、大まかに理解できる

**理解すべきこと:**
- コンパイルとは何か（人間の言語 → 機械の言語）
- インタプリタとコンパイラの違い（Python vs Go / C）
- `package.json` の `scripts` セクションの読み方
- 「ソースコード」と「成果物（ビルドアーティファクト）」の区別
- エラーメッセージの基本的な読み方（行番号、ファイル名、エラー種別）

**クイズ例:**
- 「`npm run build` を実行すると、何がどこに生成されるか？」
- 「Python は『コンパイル言語』か『インタプリタ言語』か？.pyc は何か？」

---

### Lv.2 ★★☆☆☆ — 依存関係を「管理する」

**到達目標**: パッケージマネージャーの仕組み、lock ファイルの役割、バージョニングを理解できる

**理解すべきこと:**
- パッケージマネージャー（npm, pip, go mod, cargo）の仕組み
- `package-lock.json` / `yarn.lock` の役割（なぜコミットすべきか）
- セマンティックバージョニング（SemVer: major.minor.patch）
- `dependencies` vs `devDependencies`
- `.gitignore` で `node_modules` を除外する理由

**クイズ例:**
- 「`^1.2.3` と `~1.2.3` の違いは何か？」
- 「lock ファイルを削除して `npm install` すると何が起きうるか？」
- 「この devDependency を dependencies に移したら何が変わるか？」

---

### Lv.3 ★★★☆☆ — ビルドパイプラインを「理解する」

**到達目標**: トランスパイル、バンドル、リンティングの各ステップの目的を理解し、設定ファイルを読める

**理解すべきこと:**
- トランスパイル: TypeScript → JavaScript, JSX → JavaScript, Babel の役割
- バンドル: Webpack, Vite, esbuild の目的（モジュール結合、Tree Shaking）
- リンティング・フォーマッティング: ESLint, Prettier の役割と設定
- 型チェック: `tsc --noEmit` の意味
- ソースマップ: デバッグ時に元のコードを参照するための仕組み
- 環境変数とビルド時の注入（`.env`, `process.env`）

**クイズ例:**
- 「`tsconfig.json` の `target` と `module` は何を制御しているか？」
- 「Tree Shaking とは何か？なぜバンドルサイズに影響するか？」
- 「ソースマップを本番環境に含めるべきか？メリット・リスクは？」

---

### Lv.4 ★★★★☆ — ビルドを「最適化する」

**到達目標**: ビルドパフォーマンスの改善、CI/CD パイプラインの設計、成果物の最適化ができる

**理解すべきこと:**
- CI/CD パイプラインの設計（ステージ、キャッシュ、並列化）
- Docker ビルドの最適化（レイヤーキャッシュ、マルチステージビルド）
- コード分割（Code Splitting）と遅延ロード（Lazy Loading）
- バンドル分析（webpack-bundle-analyzer）と最適化戦略
- モノレポのビルド戦略（Turborepo, Nx）
- クロスコンパイル（Go のクロスビルド、Rust のターゲット指定）

**クイズ例:**
- 「この Dockerfile のビルドキャッシュが効いていない理由を特定せよ」
- 「CI パイプラインの実行時間を半分にする改善案を3つ示せ」
- 「このバンドルサイズを30%削減する方法を提案せよ」

---

### Lv.5 ★★★★★ — ビルドシステムを「設計する」

**到達目標**: 大規模プロジェクトのビルドインフラを設計し、開発者体験とデプロイ効率を最適化できる

**理解すべきこと:**
- ビルドシステムの内部構造（依存グラフ、増分ビルド、キャッシュ戦略）
- リモートキャッシュ（Turborepo Remote Cache, Bazel Remote Execution）
- リリースエンジニアリング（Feature Flags、Canary リリース、Blue-Green デプロイ）
- コンパイラ/バンドラの設計原則（Rust の LLVM バックエンド、V8 の JIT）
- WASM（WebAssembly）の活用場面と制約
- 再現可能ビルド（Reproducible Builds）の重要性と実現方法

**クイズ例:**
- 「10人→100人にスケールする開発チームのビルドインフラを設計せよ」
- 「Feature Flags を使ったリリース戦略の利点とリスクを分析せよ」
