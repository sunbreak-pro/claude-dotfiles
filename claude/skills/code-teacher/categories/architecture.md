# 設計・アーキテクチャ

## カテゴリ概要

ソフトウェアの全体構造をどう組み立てるかに関する知識。
「なぜこの構造なのか」「別の構造だったら何が変わるか」を判断する力を育てる。

## 関連カテゴリ

- **要件定義**: アーキテクチャは要件（特に非機能要件）に基づいて決まる
- **デザインパターン**: アーキテクチャの中で使われる局所的な設計手法
- **インフラ・運用**: アーキテクチャの選択がインフラ構成に直結する

## 難易度定義

### Lv.1 ★☆☆☆☆ — 構造を「見る」

**到達目標**: プロジェクトのディレクトリ構成を見て、何がどこにあるか把握できる

**理解すべきこと:**
- フォルダ構成が意味を持つこと（`src/`, `tests/`, `config/` などの慣習）
- 「フロントエンド」と「バックエンド」の違い
- 「ライブラリ」と「アプリケーション」の違い

**クイズ例:**
- 「このプロジェクトの `src/controllers/` は何をする場所でしょう？」
- 「`package.json` と `tsconfig.json` はそれぞれ何の設定ファイルか？」

---

### Lv.2 ★★☆☆☆ — レイヤーを「知る」

**到達目標**: MVC や3層アーキテクチャなど、基本的な分離パターンの名前と目的を説明できる

**理解すべきこと:**
- MVC（Model-View-Controller）の各層の責務
- 3層アーキテクチャ（プレゼンテーション・ビジネスロジック・データアクセス）
- 「関心の分離」の意味と利点
- 単方向の依存関係（上位が下位に依存する）

**クイズ例:**
- 「このファイルは MVC のどの層に属しますか？」
- 「Controller から直接 DB にアクセスしているコードがあります。なぜ問題になり得るか？」

---

### Lv.3 ★★★☆☆ — パターンを「使い分ける」

**到達目標**: レイヤードアーキテクチャ、クリーンアーキテクチャ、ヘキサゴナルの違いを説明し、プロジェクトに適用されているパターンを特定できる

**理解すべきこと:**
- レイヤードアーキテクチャ: 層の積み重ね、各層の責務境界
- クリーンアーキテクチャ: 依存性の逆転、ユースケース駆動
- ヘキサゴナルアーキテクチャ: ポートとアダプタ
- DDD（ドメイン駆動設計）の基本用語（エンティティ、値オブジェクト、リポジトリ）
- 各パターンの適用基準（プロジェクト規模、チーム構成）

**クイズ例:**
- 「このプロジェクトはどのアーキテクチャパターンに最も近いか？根拠は？」
- 「ユースケース層を追加するとしたら、既存のどのファイルを分割すべきか？」
- 「この依存関係の方向は正しいか？クリーンアーキテクチャの原則に照らして判断せよ」

---

### Lv.4 ★★★★☆ — トレードオフを「分析する」

**到達目標**: モノリス vs マイクロサービス、同期 vs 非同期など、アーキテクチャ上の重要なトレードオフを実際のプロジェクト文脈で議論できる

**理解すべきこと:**
- モノリス vs マイクロサービス: 分割基準、通信コスト、デプロイの独立性
- 同期 vs 非同期アーキテクチャ: イベント駆動、メッセージキュー
- CQRS（コマンドクエリ責務分離）: いつ使うべきか、複雑さのコスト
- イベントソーシング: メリットとデータ整合性の課題
- サービス境界の設計: Bounded Context の特定

**クイズ例:**
- 「このモノリスをマイクロサービスに分割するとしたら、境界はどこに引くか？」
- 「現在の同期 API コールを非同期メッセージングに置き換える場合のメリット・デメリットを論じよ」
- 「CQRS を導入すべきか？現在のリード/ライト比率を踏まえて判断せよ」

---

### Lv.5 ★★★★★ — アーキテクチャを「設計する」

**到達目標**: ゼロからシステムのアーキテクチャを設計し、技術選定の根拠を説明し、将来の変更に対する拡張戦略を立案できる

**理解すべきこと:**
- 分散システムの一貫性モデル（強一貫性、結果整合性、CRDTs）
- CAP定理と実践的な適用
- スケーリング戦略（水平 vs 垂直、シャーディング）
- 進化的アーキテクチャ: 変更容易性を組み込む設計
- アーキテクチャ評価手法（ATAM、コスト便益分析）
- 技術的負債の戦略的管理

**クイズ例:**
- 「このシステムを100倍のトラフィックに対応させるための再設計案を書け」
- 「現在のアーキテクチャの最大のリスクは何か？3年後を見据えて改善案を提示せよ」
- 「新規プロダクトの技術選定ドキュメントを作成せよ（要件は以下の通り…）」
