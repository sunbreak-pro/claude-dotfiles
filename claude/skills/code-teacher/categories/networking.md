# ネットワーク

## カテゴリ概要

コンピュータ同士がどうやって通信するかに関する知識。
API コール、認証フロー、リアルタイム通信など、コードの裏で起きている通信を理解する力を育てる。

## 関連カテゴリ

- **サービスの思想**: API 設計はネットワーク知識が土台
- **インフラ・運用**: ロードバランシング、CDN、DNS はインフラ設計に直結
- **設計・アーキテクチャ**: マイクロサービス間通信はネットワークが核心

## 難易度定義

### Lv.1 ★☆☆☆☆ — 通信を「知る」

**到達目標**: Web アプリがどうやって動いているか（ブラウザ↔サーバーの関係）の基本を理解できる

**理解すべきこと:**
- クライアントとサーバーの関係
- URL の構造（プロトコル、ホスト、パス、クエリパラメータ）
- HTTP リクエストとレスポンスの基本（200, 404, 500 の意味）
- JSON とは何か（データ交換フォーマット）
- API とは何か（他のプログラムとの通信口）

**クイズ例:**
- 「`fetch('/api/users')` はどこに何を要求しているか？」
- 「ステータスコード 404 と 500 の違いは何か？」

---

### Lv.2 ★★☆☆☆ — HTTP を「使う」

**到達目標**: HTTP メソッドの使い分け、ヘッダー、認証の基本を理解できる

**理解すべきこと:**
- HTTP メソッド（GET, POST, PUT, PATCH, DELETE）の使い分けと冪等性
- リクエストヘッダー（Content-Type, Authorization, Cookie）
- レスポンスヘッダー（Cache-Control, Set-Cookie, CORS）
- Cookie とセッションの仕組み
- CORS（Cross-Origin Resource Sharing）とは何か、なぜ必要か

**クイズ例:**
- 「GET と POST の違いを3つ挙げよ」
- 「CORS エラーが出たとき、サーバー側で何を設定すべきか？」
- 「このリクエストの Authorization ヘッダーはどの認証方式を使っているか？」

---

### Lv.3 ★★★☆☆ — プロトコルを「選ぶ」

**到達目標**: REST, GraphQL, gRPC, WebSocket の特性を理解し、用途に応じて選択できる

**理解すべきこと:**
- REST の原則（リソース指向、ステートレス、統一インターフェース）
- GraphQL: オーバーフェッチ/アンダーフェッチの解消、スキーマ駆動
- gRPC: Protocol Buffers、双方向ストリーミング、バイナリ通信
- WebSocket: 全二重通信、リアルタイムユースケース
- TLS/HTTPS の仕組み（証明書、暗号化、中間者攻撃の防止）
- DNS の仕組み（名前解決の流れ）

**クイズ例:**
- 「このプロジェクトが REST を選んだ理由を推測せよ。GraphQL にすべき理由はあるか？」
- 「チャット機能を追加する場合、REST と WebSocket のどちらが適切か？」
- 「HTTPS 通信で何が暗号化され、何が暗号化されないか？」

---

### Lv.4 ★★★★☆ — 通信を「最適化する」

**到達目標**: キャッシュ戦略、リトライ設計、レート制限など、通信の信頼性とパフォーマンスを設計できる

**理解すべきこと:**
- HTTP キャッシュ戦略（ETag, Last-Modified, Cache-Control のディレクティブ）
- リトライ戦略（指数バックオフ、ジッター、冪等性の保証）
- レート制限の設計（トークンバケット、スライディングウィンドウ）
- ロードバランシングのアルゴリズム（ラウンドロビン、最小接続数、IPハッシュ）
- CDN の仕組みと設定戦略
- TCP/IP スタックの基礎（3-way handshake, 輻輳制御）

**クイズ例:**
- 「この API のキャッシュ戦略を設計せよ（更新頻度、一貫性要件を踏まえて）」
- 「外部 API 呼び出しにリトライを実装する場合、何に注意すべきか？」
- 「レート制限を実装する場合、トークンバケットとスライディングウィンドウのどちらが適切か？」

---

### Lv.5 ★★★★★ — ネットワークを「設計する」

**到達目標**: 分散システムの通信設計、ネットワークトポロジー、グローバル配信の戦略を立案できる

**理解すべきこと:**
- サービスメッシュ（Istio, Linkerd）の設計意図
- サービスディスカバリ（DNS ベース vs レジストリベース）
- ネットワーク分断への耐性設計（CAP定理の実践的適用）
- グローバル配信戦略（エッジコンピューティング、マルチリージョン）
- Zero Trust ネットワークモデル
- HTTP/3, QUIC の設計思想と適用場面

**クイズ例:**
- 「マイクロサービス間通信にサービスメッシュを導入すべきか？メリット・コストを分析せよ」
- 「このサービスをマルチリージョン展開する場合のネットワーク設計を提案せよ」
