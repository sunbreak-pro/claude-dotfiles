# 概念カテゴリ一覧

## 使い方

ユーザーが学習したいカテゴリを選択したら、該当する `.md` ファイルを Read して、そのレベル定義に従って教材を作成・解説する。複数カテゴリにまたがるトピックの場合は、関連カテゴリも Read する。

## カテゴリ一覧

| カテゴリ | ファイル | 一言説明 |
|----------|---------|---------|
| 設計・アーキテクチャ | `architecture.md` | ソフトウェアの全体構造をどう組み立てるか |
| 要件定義 | `requirements.md` | 何を作るか・なぜ作るか・どこまで作るか |
| デザインパターン | `design-patterns.md` | 繰り返し現れる設計問題の定番解法 |
| データベース | `database.md` | データの永続化・構造化・アクセス |
| ネットワーク | `networking.md` | コンピュータ同士の通信の仕組み |
| コンパイル・ビルド | `compilation-build.md` | ソースコードが実行可能になるまでの過程 |
| サービスの思想 | `service-philosophy.md` | ソフトウェアをサービスとして提供する哲学 |
| インフラ・運用 | `infrastructure.md` | ソフトウェアが動く環境とその維持 |

## カテゴリ間の関係

```
要件定義 ─────→ 設計・アーキテクチャ ←──── サービスの思想
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
   デザインパターン  データベース  ネットワーク
          │         │         │
          └─────────┼─────────┘
                    ▼
            コンパイル・ビルド
                    │
                    ▼
              インフラ・運用
```

上流（要件定義・サービスの思想）の判断が下流（インフラ・運用）に影響するが、逆方向の制約もある（インフラの制約がアーキテクチャを限定するなど）。

## 各カテゴリの Lv.1-5 共通フレームワーク

全カテゴリで難易度は以下の動詞で段階を表現する:

| レベル | 動詞 | 意味 |
|--------|------|------|
| Lv.1 | 知る/見る | 用語と基本概念を認識できる |
| Lv.2 | 使う/理解する | 既存のものを正しく使える |
| Lv.3 | 適用する/設計する（小） | 小〜中規模の文脈で自分で判断できる |
| Lv.4 | 最適化する/分析する | トレードオフを比較し最適な選択ができる |
| Lv.5 | 戦略的に設計する | 大規模・長期的な視点で構想・立案できる |
