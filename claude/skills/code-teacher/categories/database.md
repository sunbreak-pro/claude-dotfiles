# データベース

## カテゴリ概要

データの永続化、構造化、アクセスに関する知識。
「なぜこのテーブル設計なのか」「このクエリは効率的か」を判断する力を育てる。

## 関連カテゴリ

- **設計・アーキテクチャ**: データモデルはアーキテクチャの中核
- **要件定義**: データ構造は要件から導出される
- **インフラ・運用**: DB のスケーリングや可用性はインフラ設計に影響

## 難易度定義

### Lv.1 ★☆☆☆☆ — データを「保存する」

**到達目標**: DB の基本概念を理解し、簡単なCRUD操作のコードを読める

**理解すべきこと:**
- データベースとは何か（ファイル保存との違い）
- テーブル・行・カラムの概念
- 主キー（Primary Key）の役割
- 基本的な CRUD（Create, Read, Update, Delete）
- ORM とは何か（コードと SQL の対応関係）

**クイズ例:**
- 「このモデル定義は何のテーブルを表しているか？」
- 「この ORM のクエリは SQL に直すとどうなるか？」

---

### Lv.2 ★★☆☆☆ — リレーションを「理解する」

**到達目標**: テーブル間のリレーション（1:1, 1:N, N:N）を読み取り、JOIN の動作を理解できる

**理解すべきこと:**
- 外部キー（Foreign Key）の仕組みと目的
- リレーションの種類（1:1, 1:N, N:N）と中間テーブル
- JOIN の基本（INNER, LEFT, RIGHT）
- NULL の意味と扱い方
- 基本的なインデックスの概念（なぜ検索が速くなるか）

**クイズ例:**
- 「このテーブル間のリレーションを図示せよ」
- 「この N:N リレーションの中間テーブルにはどのカラムが必要か？」
- 「この WHERE 句に対してインデックスは効いているか？」

---

### Lv.3 ★★★☆☆ — スキーマを「設計する」

**到達目標**: 正規化・非正規化を判断し、適切なスキーマを設計できる。マイグレーションの安全性を評価できる

**理解すべきこと:**
- 正規化（1NF〜3NF）の各段階と目的
- 非正規化が必要な場合の判断基準（パフォーマンス vs データ整合性）
- トランザクションと ACID 特性
- マイグレーション戦略（安全なカラム追加、破壊的変更の回避）
- N+1 問題の認識と対策

**クイズ例:**
- 「このテーブルを第3正規形にせよ」
- 「このマイグレーションはダウンタイムなしで実行できるか？」
- 「N+1 問題が発生している箇所を特定し、修正案を示せ」

---

### Lv.4 ★★★★☆ — パフォーマンスを「最適化する」

**到達目標**: クエリの実行計画を読み、インデックス戦略を設計できる。RDB vs NoSQL の選定判断ができる

**理解すべきこと:**
- EXPLAIN/実行計画の読み方（Full Scan, Index Scan, Nested Loop）
- 複合インデックスの設計（カーディナリティ、カバリングインデックス）
- RDB vs NoSQL の選定基準（構造化 vs スキーマレス、一貫性 vs 可用性）
- コネクションプーリング
- デッドロックの原因と回避策
- 楽観的ロック vs 悲観的ロック

**クイズ例:**
- 「この EXPLAIN 結果を読み、ボトルネックを特定せよ」
- 「このユースケースには RDB と NoSQL のどちらが適切か？根拠は？」
- 「デッドロックが発生しうる箇所を特定し、回避策を示せ」

---

### Lv.5 ★★★★★ — データ基盤を「設計する」

**到達目標**: 分散データベースの設計、データパイプライン、長期的なデータ戦略を立案できる

**理解すべきこと:**
- 分散データベースの一貫性モデル（強一貫性 vs 結果整合性）
- シャーディング戦略（ハッシュ、レンジ、ジオグラフィック）
- CQRS とイベントソーシングのデータモデル
- データパイプライン設計（ETL/ELT、ストリーミング vs バッチ）
- マルチテナントのデータ分離戦略
- データガバナンスと GDPR/個人情報管理

**クイズ例:**
- 「このサービスのデータを100倍に成長させる場合のシャーディング戦略を設計せよ」
- 「マルチテナント化する場合、データ分離をどう実現するか？3案比較せよ」
