# Task Tracker

作業開始・中断・終了時にタスク進捗と履歴を更新する。並行チャットの衝突を避けるため per-chat ファイル方式が標準で、従来の MEMORY.md / HISTORY.md 方式（legacy）にも対応する。

## モード判定（起動時・2 段）

**Step 1 書き込み有無**: Skill の `args` を空白で split した先頭トークンが `inspect` なら **inspect モード**（Read only）。それ以外（start / pause / end / 未指定）は通常モード。

**Step 2 読み書き先**:

| 条件                                                                                              | モード       | 書き込み先                                                        |
| ------------------------------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------- |
| `.claude/memory/` があり、かつ `.claude/memory/INDEX.md` または `.claude/memory/chat-*.md` がある | **per-chat** | `memory/chat-<self>.md` + `history/chat-<self>.md` + INDEX 再生成 |
| 上記不成立                                                                                        | **legacy**   | `.claude/MEMORY.md` + `.claude/HISTORY.md`                        |

マーカーを AND にしているのは、別目的で `.claude/memory/` が偶然ある場合の誤判定を防ぐため。`chat-*.md` も含めるのは、スクリプト方式では INDEX.md が git 非追跡で新規 clone に無いことがあるため。

per-chat では `<self>` を `.claude/comm/.session-name` から読む。次のいずれかなら**エラーで停止**する（自己判定不能のまま書くと他チャットの memory を上書きする）: ファイルが無い / 中身が空 / `chat-` プレフィックスを含む / 空白・`/`・`.`・`..` を含む。停止時は「`echo <本体部分のみ> > .claude/comm/.session-name` で作成してください（例: `engineer`, `main`）」と提示する。inspect モードは per-chat 成立時のみ使え、legacy では即エラー停止。

## 状態判定

| 発話・状況                                      | 判定    | フロー                                                           |
| ----------------------------------------------- | ------- | ---------------------------------------------------------------- |
| 「作業開始」「再開」「次のタスクやる」          | START   | 作業開始（並行チャット競合チェック込み）                         |
| 「進捗確認」「今どこまで」「他チャットの状況」  | INSPECT | inspect（書き込みなし）                                          |
| 「中断」「途中保存」「ちょっと止める」          | PAUSE   | 作業途中                                                         |
| 「作業終了」「コミットして」「PR 出せる状態に」 | END     | session-verifier を先に実行 → 作業終了                           |
| 曖昧                                            | —       | memory を読んで状態から判定。決められなければ PAUSE を既定にする |

## ファイル

| per-chat                                         | legacy                       | 役割                               |
| ------------------------------------------------ | ---------------------------- | ---------------------------------- |
| `.claude/memory/chat-<self>.md`                  | `.claude/MEMORY.md`          | タスクトラッカー（3 セクション）   |
| `.claude/history/chat-<self>.md`                 | `.claude/HISTORY.md`         | 変更履歴（先頭追記・降順）         |
| `.claude/history/archive/YYYY-MM/chat-<self>.md` | `.claude/HISTORY-archive.md` | ローリングアーカイブ（5 件超過分） |
| `.claude/memory/INDEX.md` / `history/INDEX.md`   | —                            | 全チャット集約ビュー（自動生成）   |

### MEMORY 形式（両モード共通）

```markdown
# MEMORY (chat-<self>) ← legacy は `# MEMORY.md - タスクトラッカー`

## 進行中

### 🔧 タスク名（着手日: YYYY-MM-DD） ← ⏸️ は中断中

**対象**: `関連ファイル/ディレクトリ`
**計画書**: `.claude/docs/vision/plans/YYYY-MM-DD-task-slug.md` ← あれば

- 前回: —
- 現在: 現在のサブタスク
- 次: 次のサブタスク

## 直近の完了 ← 最大 3 件

- タスク名 ✅（YYYY-MM-DD）

## 予定 ← 順序あり

- 次に着手予定のタスク
```

タスクなしは `（なし）`。3 セクション以外は追加しない。

### HISTORY 形式

```markdown
# HISTORY (chat-<self>) ← legacy は `# HISTORY.md - 変更履歴`

### YYYY-MM-DD - タイトル

#### 概要

1〜2 文。

#### 変更点

- **カテゴリ名**: 具体的な変更内容
```

中断記録は簡易形式 `- YYYY-MM-DD: [途中] タスク名 — 進捗の要約`。既存行は編集しない。

## INDEX 再生成（per-chat のみ・書き込み後に必ず）

`.claude/hooks/regen-index.sh` が**あれば** `bash .claude/hooks/regen-index.sh` を 1 回実行するだけ（INDEX.md は git 非追跡の派生物。LLM で書き換えない・stage しない）。**無ければ**インライン方式: `memory/chat-*.md` 全件から 進行中 / 直近の完了（各チャット最大 3 件）/ 予定 を `[chat-<name>] 項目 — 日付` の形で 1 ファイルに集約し、`history/chat-*.md` の先頭エントリを時系列降順 5 件で集約する。見出しは `# MEMORY INDEX (auto-generated by task-tracker)` / `# HISTORY INDEX (...)`、`最終更新: YYYY-MM-DD HH:MM:SS (chat-<self>)` を付け、tracked ファイルとして stage する。再生成に失敗してもチャット別ファイルの書き込みは成功扱い（次回再試行）。

## 作業開始フロー

0. `.claude/active-sessions/` に自分以外のセッションファイルがあれば各ファイルを Read し、cwd / branch / 担当領域を突き合わせて、共有ファイルや同一ブランチに触る他チャットがいないか確認する。競合が疑われるなら報告に書き、触る範囲を自分の担当に限定して進める
1. モード判定 + self 解決（上記）
2. memory を Read（per-chat で無ければ MEMORY 形式の初期テンプレートで作成）
3. 「予定」の先頭タスクを「進行中」へ `### 🔧` ブロックとして移動（対象ファイルを推定して記載、前回: —）。既に進行中があっても追加開始可
4. Edit で更新 → INDEX 再生成 → 結果を表示

## 作業途中フロー

1. モード判定 + self 解決
2. 該当タスクを `### 🔧` → `### ⏸️`、前回 / 現在 / 次を最新化
3. history 先頭に中断記録を追記
4. INDEX 再生成 → 結果を表示

## 作業終了フロー

> 実行タイミングは **session-verifier が緑になった直後**。ユーザーの確認も実装 PR の merge も待たない（merge は人の手番なので待つと固まる）。PR の状態は書いた時点の実測（open / merged）で記す。tracker の更新を実装ブランチに載せない運用のプロジェクトでは専用ブランチ（例: `chore/tracker-<chat>-YYYYMMDD`）を切って commit → PR まで進める。

1. モード判定 + self 解決。memory と history を並列 Read
2. memory: 完了タスクの `###` ブロックを削除 → 「直近の完了」先頭に `- タスク名 ✅（YYYY-MM-DD）`（3 件超は削除）→ 進行中が空なら `（なし）`
3. history 先頭に詳細エントリ（概要 / 変更点）
4. **計画書アーカイブ**（実行者は本スキル。code-plan-editor は参照のみ）: `.claude/docs/vision/plans/YYYY-MM-DD-*.md`（fallback `.claude/YYYY-MM-DD-*.md`）から、`**Task**:` がタスク名と一致するか slug が部分一致する計画書を探す。あれば **乖離レビュー 3 行**を Worklog に必ず書き、Status を `COMPLETED` に更新し、`.claude/archive/` へ `mv`（無ければ作成）。history の完了記録に `（計画書: archive/ファイル名）` を付記。無ければサイレントスキップ

   **乖離レビュー 3 行**（「特になし」も明記する）:
   1. **スコープ逸脱**: Scope 宣言の外を触ったか。触ったなら何をどういう判断で
   2. **AC 免除**: 満たせなかった Acceptance Criteria とその扱い
   3. **途中で出た判断の行き先**: 追加要望・QA の Suggestion・verifier の非 Blocking finding をどこへ送ったか（判断キュー / Issue # / decisions / 破棄）

   規約級（今後の全作業に効く）の内容は `decisions/` か `docs/known-issues/` へ昇格させる。行き先の空欄を残さない

5. ローリングアーカイブ: history が 5 件超なら最古エントリを archive へ（per-chat は `history/archive/YYYY-MM/chat-<self>.md`、legacy は `HISTORY-archive.md`）。移動するのは `### YYYY-MM-DD - タイトル` で始まるエントリ本文だけで、ファイル末尾の索引フッター（`./archive/...` への相対リンク行）は生きているファイルに残す（行範囲で切り出すとフッターごと運んでリンク切れになる。2026-08-31 life-editor PR #1344）
6. INDEX 再生成
7. **scope-drift 検出**（per-chat 必須 / legacy はスキップ）: `git status --porcelain` の各パスを分類する
   - **self-owned**（commit 対象）: `memory/chat-<self>.md` / `history/chat-<self>.md` / インライン方式のときのみ両 INDEX.md / 該当時の `history/archive/.../chat-<self>.md` / Step 4 で archive した計画書 / 実装変更ファイル（全変更コミット時にユーザーが明示したパス）
   - **foreign**（触らない）: 他チャットの `chat-<other>.md`・outbox / 自分が触っていない実装ファイル
   - **unknown**: 上記いずれでもない新規 untracked 等。安全側で foreign 扱い

   foreign / unknown があっても止まらず、**既定 = self-owned だけを pathspec で stage して進み、除外したパスを報告に列挙する**。ユーザーが「含めたい」と明示したパスだけ追加する。abort はユーザーが明示したときだけ

8. **commit + push**
   - 変更種別: 計画書アーカイブを実行した（= 実装計画を実装した）→ 全変更コミット / なし → メタファイルのみ
   - ステージング:
     - per-chat・メタのみ: `git add .claude/memory/chat-<self>.md .claude/history/chat-<self>.md`（+ archive 移動分。インライン方式のときだけ両 INDEX.md も）。スクリプト方式で INDEX.md を `git add` しない（ignore 済み。`-f` で足すと衝突源が復活する）
     - per-chat・全変更: **`git add -A` は使わない**。実装ファイルも含めてパスを明示列挙する（並行チャットの未コミット変更を巻き込まないための中核設計）
     - legacy・メタのみ: `git add .claude/MEMORY.md .claude/HISTORY.md`（+ 必要なら HISTORY-archive.md）
     - legacy・全変更: `git add -A`（単一セッションのプロジェクトのみ）
   - `git diff --cached --stat` で確認し、空ならスキップ。メッセージは英語で `Update task tracker: {完了タスク名}`（全変更時は実装内容を反映）→ `git commit` → `git push`。push 失敗（リモート未設定・認証）は報告してスキップ、commit は維持
9. 結果を表示。計画書アーカイブを実行した場合は PR を git-branch-flow で出す

## inspect モードフロー

他チャットの状況を一覧する。**書き込み一切なし**（Edit / Write / INDEX 再生成 / git 操作を行わない）。`args` の先頭が `inspect` なら後続トークンは無視する。

1. モード判定のみ（self 解決不要。per-chat 不成立なら「per-chat 機構が未導入のプロジェクトでは使用不可」でエラー停止）
2. `.claude/memory/chat-*.md` を Glob（INDEX.md 除外）し、同一メッセージで並列 Read
3. チャットごとに 進行中 / 直近完了（上位 3）/ 予定（上位 3）を見出し抽出で整形して表示（自分の chat も含める。勝手に要約しすぎない）。`inspect --history` なら `history/chat-*.md` の直近 3 エントリも
4. INDEX と乖離していたら「INDEX が古い可能性。次回 start / end で再生成」と注記

## 規約

- 日付はシステムの実行時日付。ファイル更新は Edit（sed / awk は使わない）。計画書の移動は `mv`
- 作業開始時は memory のみ更新（history は終了時）。複数タスク並行時、終了は完了タスクだけ処理し他の進行中には触れない
- 他チャットの `chat-*.md` は読み取り専用（単一書込者原則）
- タスク状態の正本は本スキル。sui-memory（Mac 専用・セッション横断の自動要約）と矛盾したら本スキルを優先する
