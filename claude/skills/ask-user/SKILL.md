# Ask User

ユーザーへの質問は **AskUserQuestion (選択式)** を原則必須とする。文章での自由入力 (Other) は AskUserQuestion 側に自動で用意されるため、文章質問はほぼ不要。

## 設計思想

- **ユーザーの入力負荷を最小化**: 選択肢クリックは 1 タップ、文章入力は数十秒〜数分
- **質問の質を担保**: テンプレート化で「open question / 曖昧な二択 / 質問連発」を防止
- **Recommended で意思決定を加速**: Claude の推奨を先頭に明示し、迷ったら即決できるようにする
- **可逆 / 不可逆の区別**: 不可逆操作の前は必ず確認、可逆な小変更は問わない

## 起動タイミング

### 自動起動（曖昧と判定したとき）

以下に該当したら、勝手に進める前に AskUserQuestion で確認する：

- 要件にスコープの幅がある（「リファクタして」「整理して」など範囲未指定）
- 実装方針が 2 つ以上ある（ライブラリ選択 / アーキテクチャ選択 / 命名選択）
- 破壊的・不可逆的アクションの直前（削除 / force push / DB drop / migration apply）
- 曖昧な指示語（「これ」「さっきの」「いい感じに」）でターゲット候補が複数ある
- 既存コードと衝突する設計判断（既存パターンを壊すか合わせるか）

### 明示起動

- ユーザーが `/ask-user` と打った
- ユーザーが「選択式で聞いて」「テンプレートで質問して」と言った

### 起動しない場面

- 単純なタイポ修正
- 既に具体的で明確な指示が与えられている
- 「すぐやって」「即実行」が明示されている
- 純粋な情報報告（「進捗を見せて」など、質問を返す必要がない）

## AskUserQuestion 使用ルール

### 構造制約（厳守）

| 項目           | 制約                                                 |
| -------------- | ---------------------------------------------------- |
| 1 回の質問数   | 1〜4 個（5 個以上 NG）                               |
| 各質問の選択肢 | 2〜4 個（5 個以上 NG）                               |
| `header`       | 最大 12 文字（チップ表示）                           |
| `label`        | 1〜5 単語（簡潔に）                                  |
| `description`  | 1〜2 文でトレードオフを必ず書く                      |
| Recommended 印 | label 末尾に `(Recommended)` を 1 つだけ、先頭に配置 |
| Other 選択肢   | 自動付与されるので**自分で書かない**                 |

### preview の使い所

`preview` フィールドはコード断片 / ASCII モックアップ / 設定ファイル例など「視覚比較が役立つもの」のみ。単純な好み質問では使わない。**multiSelect では使えない**。

### multiSelect の使い所

選択肢が排他でない場合のみ `multiSelect: true`。例: 「有効化したい機能を全て選んで」。デフォルトは `false`。

## 質問テンプレート

### Pattern A: スコープ確認

```
question: "今回の変更スコープはどこまでにしますか？"
header:   "Scope"
options:
  - 最小限 (Recommended) — バグ部分のみ修正、周辺は触らない
  - 関連箇所も含む — 同じパターンの類似箇所も併せて修正
  - 全面リファクタ — ファイル全体を整理
```

### Pattern B: 方針選択

```
question: "どの実装方針で進めますか？"
header:   "Approach"
options:
  - 既存パターン踏襲 (Recommended) — 既存規約と整合
  - 新パターン導入 — 既存からの逸脱、規約更新が必要
  - ライブラリ追加 — 依存増、保守コスト増
```

### Pattern C: 命名選択

```
question: "<対象> の名前はどれにしますか？"
header:   "Name"
options:
  - <候補1> (Recommended) — 短く直感的
  - <候補2> — 用途を明示
  - <候補3> — 既存命名規則に合わせる
```

### Pattern D: 実行可否確認（破壊的操作前）

```
question: "<具体的な操作内容>を実行してよいですか？"
header:   "Confirm"
options:
  - 実行する — そのまま進める
  - 中止する (Recommended) — 別アプローチを検討
  - 内容を変えて再提案 — 範囲や条件を調整して再提示
```

### Pattern E: 配置先選択

```
question: "ファイルをどこに置きますか？"
header:   "Path"
options:
  - <既存パス>/ (Recommended) — 既存構造に従う
  - <代替パス>/ — 機能的に別カテゴリ
  - 新ディレクトリを切る — 規模が大きい場合のみ
```

### Pattern F: 優先度判定

```
question: "この問題の対応優先度は？"
header:   "Priority"
options:
  - 即修正 (Recommended) — 今のセッションで対応
  - 別タスクに切り出し — MEMORY.md に予定として記録
  - 様子見 / 記録のみ — known-issues に記録するだけ
```

### Pattern G: セッション遷移（session-manager 連携）

```
question: "現在の状態でどう進めますか？"
header:   "Session"
options:
  - 作業を再開 (Recommended) — 次のサブタスクへ
  - 中断して保存 — 進捗記録のみ
  - 完了として記録 — HISTORY 更新 + コミット
```

### Pattern H: UI / レイアウト選択（preview 活用）

視覚比較が必要な時のみ preview を付ける。例：

```
question: "ボタンのレイアウトはどれにしますか？"
header:   "Layout"
options:
  - 横並び (Recommended)
    preview: |
      [ Cancel ] [ Save ]
  - 縦並び
    preview: |
      [   Save   ]
      [  Cancel  ]
  - フローティング
    preview: |
                [ Save ]
                [ Cancel ]
```

## Anti-Pattern

| アンチパターン                           | なぜダメか                               |
| ---------------------------------------- | ---------------------------------------- |
| 「どうしましょうか？」 (open question)   | 選択肢がない＝結局ユーザーが文章で答える |
| 「良いですか？」 (Yes/No 二択)           | 分岐情報が乏しい。具体的な代替を提示する |
| 1 メッセージに 5 個以上の質問            | ユーザーが疲れる。最重要 4 個に絞る      |
| 「他に自由に書いて」の選択肢を自分で追加 | Other は自動付与されるので二重           |
| `description` が空 / `...` のみ          | 選択肢の意味が伝わらない                 |
| Recommended を複数 / つけない            | 推奨が分散して即決できない               |
| 文章質問を毎ターン繰り返す               | このスキルの存在意義に反する             |

## 出力フォーマット

質問前に **1〜2 文** で「何を確認したいか」を述べてから AskUserQuestion を呼ぶ：

```
<簡潔な前置き 1〜2 文>
[AskUserQuestion 呼び出し]
```

質問後に追加の解説や前置きを長く書かない（選択肢の `description` で十分伝わる）。

## 例外: 文章質問が許されるケース

選択肢を 4 個以内に列挙できない / Other が本質的に必要な場合のみ：

- 自由命名（候補が無限）：「ブランチ名を入力してください」
- ID / URL / 数値の入力：「対象 PR 番号を教えてください」
- 長文の意図確認：「このタスクで実現したいゴールを 1〜2 文で」

ただし、候補が思いつくならまず選択式で提示し、**「Other で自由入力できます」と明記する**。

## 起動の鉄則

- **質問するなら必ず AskUserQuestion**（文章で聞かない）
- **Recommended を必ず 1 つ先頭に置く**
- **2〜4 個の選択肢、1〜4 個の質問**
- **不可逆操作の前は必ず確認、可逆な小変更は問わない**
- **質問しない判断もする**（明確な指示なら即実行）
