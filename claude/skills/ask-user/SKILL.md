# Ask User

ユーザーは見ていない。質問すると作業が止まるので、**原則は仮定を置いて進め、置いた仮定を最終報告に書く**。聞いてよいのは次の 2 つだけ。

1. 不可逆操作の直前（削除 / force push / DB drop / migration apply / 外部送信）
2. どの仮定を置いても成果物が無意味になる（実装方針が根本から分かれ、片方を選ぶと作り直しになる）

「範囲が曖昧」「命名が複数ある」「既存パターンと衝突する」は 1〜2 に当たらない。推奨案を自分で選んで進め、報告で「仮定: ○○」と示す。

## 聞くときの型（AskUserQuestion）

| 項目           | 制約                                                                |
| -------------- | ------------------------------------------------------------------- |
| 質問数         | 1〜4 個                                                             |
| 各質問の選択肢 | 2〜4 個。Other は自動付与されるので書かない                         |
| `header`       | 12 文字以内                                                         |
| `label`        | 1〜5 単語。推奨案を先頭に置き `(Recommended)`                       |
| `description`  | 1〜2 文でトレードオフを書く                                         |
| `preview`      | コード断片 / ASCII モックの視覚比較にだけ使う。multiSelect では不可 |

質問前に 1〜2 文で「何を確認したいか」を述べ、質問後に長い解説を足さない。

### 不可逆操作の確認（Pattern D）

```
question: "<具体的な操作内容>を実行してよいですか？"
header:   "Confirm"
options:
  - 実行する — そのまま進める
  - 中止する (Recommended) — 別アプローチを検討
  - 内容を変えて再提案 — 範囲や条件を調整して再提示
```

## 文章質問が許されるケース

選択肢を 4 個以内に列挙できないときだけ（自由命名 / ID・URL・数値の入力 / 長文の意図確認）。候補が思いつくならまず選択式で出し、「Other で自由入力できます」と添える。
