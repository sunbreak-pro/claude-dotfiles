# 言語固有リファクタリング考慮事項

プロジェクト固有スキルを編集する際の参考資料。
各言語で「関数/クラスの分割」「パフォーマンス最適化」の判断基準が異なる点をまとめる。

## 分割判断の言語差

### 動的型付け言語（Python, Ruby, JavaScript）
- 型情報がないため、関数名と引数名で意図を明確にする重要性が高い
- ダックタイピングによるインターフェース分割が柔軟
- テストによる安全ネットが特に重要（型チェッカーがない分）

### 静的型付け言語（TypeScript, Java, Rust, Go, C++）
- 型システムをリファクタリングの安全ネットとして活用
- インターフェース/トレイト/プロトコルによる抽象化が言語機能で支援される
- コンパイラエラーで破壊的変更を検出可能

### 関数型寄りの言語・パターン
- 副作用の分離（純粋関数 vs I/O）が最優先の分割軸
- パイプライン/チェーンによる処理合成を活用
- 不変データ構造を基本とする

## パフォーマンス最適化の言語差

**メモリ管理モデルで大きく異なる:**
- GC言語（Python, Java, Go, JS）: アロケーション頻度とGCプレッシャーに注意
- 所有権モデル（Rust）: ライフタイムと借用で制御、clone()の削減が主要テーマ
- 手動管理（C++）: RAII、ムーブセマンティクス、スマートポインタの適切な使用

**並行処理モデルで異なる:**
- スレッドベース: Java, C++, Rust
- コルーチン/async: Python(asyncio), Kotlin(coroutines), JS(Promise)
- CSPモデル: Go(goroutine + channel)
